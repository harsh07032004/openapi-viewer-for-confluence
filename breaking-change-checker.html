OpenAPI breaking-change checker

Paste the old and new versions of an OpenAPI 3.x or Swagger 2.0 spec (YAML or JSON) to see what could break existing API clients. Everything runs in your browser; your specs are never uploaded.

Track API changes on your Confluence pages

OpenAPI & Swagger Viewer for Confluence renders your spec on a page with Swagger UI. It runs on Atlassian Forge and is eligible for Runs on Atlassian, so your spec never leaves your site.

What counts as a breaking change

GroupExamples
BreakingEndpoint removed, new required parameter or request field, parameter now required, type changed, response field removed, success response removed, enum value removed from a request, authentication added
CompatibleEndpoint added, optional parameter or field added, response added
NotesEndpoint deprecated, new enum value in a response, API version changed

A change inside a shared schema (components/schemas or definitions) is listed once, with the endpoints that use it. Local $refs and allOf are followed; external $ref URLs are not fetched, so bundle your spec into one file first (for example with redocly bundle). Descriptions and examples are not compared.
